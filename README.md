# Gamo Zone Landslide Early Warning — Sample Prototype

A working, free, end-to-end example of a daily landslide risk nowcast:
**constant engineering parameters + daily rainfall → daily risk, shown on a public webpage.**

This is a demo with simulated data, built so you can see every piece of the
pipeline working together before connecting it to real data.

---

## What's in this folder

| File | What it does |
|---|---|
| `data/engineering_parameters.csv` | Static site data: slope, soil, geology, and a susceptibility score for 6 sample Gamo Zone locations. Change rarely (only when you do a new field survey). |
| `data/rainfall_sample_30day.csv` | Simulated daily rainfall (generated by `model.py`). In a real system this would come from CHIRPS/IMERG instead. |
| `model.py` | The model: combines susceptibility + rainfall → a daily risk score and risk level (Low/Medium/High/Very High) per site. Writes `results.json`. |
| `results.json` | The model's output — one record per site per day. This is what the dashboard reads. |
| `dashboard.html` | The public-facing webpage. Self-contained — open it directly in any browser, no install needed. |
| `.github/workflows/daily_update.yml` | Automation: tells GitHub to re-run `model.py` every day for free, with no server. |

---

## Step 1 — Try it right now (no setup)

Just open `dashboard.html` in any web browser (double-click the file, or drag it
into a browser tab). You'll see:
- A map of the 6 sample sites, color-coded by risk
- A day slider covering 30 simulated days (drag it, or hit Play)
- A rainfall + risk chart for whichever site you click
- A placeholder section explaining the separate 30-year outlook concept

This works completely offline because the sample data is embedded in the file.

## Step 2 — Regenerate the sample data (optional)

If you want to see the model actually run and produce new numbers:

```bash
python3 model.py
```

This rewrites `results.json` with a freshly simulated 30-day rainfall sequence.
(To see it in `dashboard.html`, you'd re-embed the new `results.json` into the
HTML file — this manual step goes away once you deploy it properly, see Step 4.)

## Step 3 — Replace sample data with your real data

- Edit `data/engineering_parameters.csv` with your actual surveyed sites
  (real slope angles, soil data, coordinates, susceptibility scores).
- In `model.py`, replace the `simulate_rainfall()` function with a real call to
  CHIRPS or IMERG for your site coordinates. This is the only part that
  changes — the risk-scoring logic can stay the same as a starting point.

## Step 4 — Make it live and free, for anyone to view

1. Create a free GitHub account and a new repository, upload this folder to it.
2. GitHub Actions (already configured in `.github/workflows/daily_update.yml`)
   will automatically run `model.py` every day and commit the new `results.json`
   — no server, no cost.
3. Turn on **GitHub Pages** for the repository (Settings → Pages → deploy from
   the main branch) so `dashboard.html` gets a public URL anyone can open.
4. Update `dashboard.html` to `fetch('results.json')` instead of using embedded
   data, so it always shows the latest day without needing to be rebuilt.

At that point, anyone with the link can check daily risk from their own
computer or phone, anywhere — updated automatically, for free.

## Notes on the model logic (for your report/thesis)

- `risk_score = 0.5 * susceptibility + 0.5 * rain_factor * susceptibility * 1.3`
- `rain_factor` is the 3-day antecedent rainfall normalized against a 150 mm
  saturation reference — a simple, transparent placeholder threshold.
- This is intentionally simple so it's easy to explain and defend. Once you
  have real landslide event records (e.g. from NASA's COOLR catalog or your
  own field data), you can replace this rule with a trained model (logistic
  regression or similar) calibrated on actual events.
